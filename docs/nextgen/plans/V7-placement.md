# V7 placement feedback

The cursor footprint is a presentation read of the native power placement rules. `PlacementPreviewState` uses simulation coordinates and facing, with optional fixed-capacity points for twin Glacier, twin Pylon and Napalm triplet. Glacier and Bulwark preserve the catalog wall length/thickness and perpendicular facing. Napalm preserves the real pool radius (80 for triplet); Tesla shows the actual 18-unit support footprint rather than presenting its attack reach as a collision footprint.

A single three-instance draw is constructed before normal material warmup. It uses no texture, shader variants, per-press GPU allocation, post pass or Low-only branch. Dashed element outlines have open interiors; blocked marks add interrupted crosses and a warm edge. The parent ability owner binds the existing priority mask so hostile warnings and bodies retain priority. Reduced motion does not animate the footprint.

The minimal UI change is confined to `gameAdapter.ts` and `Hud.ts`. The adapter feature detects a direct renderer `setPlacementPreview` first, then the stable callback owned by `LazyAbilityVisuals` on public `scene.userData`; the old optional invalid-only hook remains compatible. The UI never changes a simulation field. Target-aware pointer reads reuse bounded scratch records, and geometry reads use the same native traversal helper. The slot keeps its charge/cooldown/state cue and says `REPOSITION` when the stored charge cannot be placed. Detailed machinery/ground explanations stay beside the cursor. A denied footprint remains at its attempted mark for .95 seconds and the passive existing cursor label lasts .9 seconds, followed by live aim. Blur, resize, pause, room change and disposal clear stale feedback.

Two fidelity qualifications follow from the unchanged game contract: Bulwark is directional and fixed 70 units in front of the marine; it is not cursor placed. Point powers clamp to their native maximum range and accept that clamped placement. Therefore the UI shows the actual clamped footprint and never invents a blocked `Out of range` result. Simulation denials carry `blocked`, not a more detailed cause. Machinery versus unsupported ground copy is a read-only geometric explanation and never decides acceptance.

Tests retain native acceptance: the new adapter tests compare actual resolved deployments against the preview for every rig and the three placement augments. They also assert no gameplay mutation, native range clamp, blocked native refusal, pooled pointer scratch and legacy hook behavior. The renderer tests cover exact wall orientation, physical Pylon/Napalm support, per-point blocked marks, reused GPU buffers, hidden/invalid clearing and exact-once disposal. The HUD contract tests cover one-second denial retention, resuming live aim, cursor label, charge cue, pause and disposal. One existing presentation pin changes `Need clear ground` in the slot to `REPOSITION`; the stored charge and non-zero-cooldown guarantees remain.
