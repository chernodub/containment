At the current `WorldDressing` call site, geometry writers accumulate transformed geometry into material buckets. The dressing root is not attached to `world` until after `addConstructionLanguage` returns and those buckets are merged. No await, animation, source-transform or source-attribute mutation occurs between sampler construction and its two probe loops. Newly authored narrative/skin geometry was therefore absent from both the old world ray and the new static snapshot, even though writer calls occur between loops. This immutability assumption is an explicit limit: future callers must rebuild the sampler if source transforms, geometry, layers, draw ranges or relevant material policies change.

Query geometries own only new index buffers; source position attributes/materials/bounding objects are shared read-only. Queries are never added to the scene or uploaded, so disposing query geometry releases its CPU owner without disposing original geometry/material or deleting a rendered source attribute. Clearing cells/geometries/fallback/hits removes retained references; repeated disposal is harmless and further querying throws. Synchronous exceptional exit leaves only garbage-collectable CPU objects, not uploaded GPU resources. Computing missing source boundingSphere matches native Three's lazy behavior. Nonfinite vertices now fail fast rather than building an invalid index; that is validation of malformed input, not an assertion of equality for invalid geometry.
