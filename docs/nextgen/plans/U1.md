# U1 implementation plan

## Decisions
- Preserve production loading, input gates, graphics recovery, checkpoint warnings and DOM hooks in an application bootstrap; extract screen and HUD ownership before redesign.
- Interface direction: industrial navigation instruments, cyan-white friendly light, amber kinetic, ice cryo, orange pyro, violet arc, red-orange danger, gold rewards. Dark local glass and restrained chamfers. Display/body type self-hosted under OFL.
- Edge furniture protects a central play area; relocation remains driven by renderer.playerScreenBounds for current and future cameras.
- Optional A1/G1 surfaces pass through gameAdapter with runtime feature detection. Fixtures prove rig selection, cooldown/cast/denied/Overdrive, graphics persistence and stats without sim edits.
- Pooled combat text and capped enemy-type/elite/attack/distance threat indicators; optional geometry radar. Add a varied-distance kiting capture.

## Modules and ownership
- Lead: application.ts, shell.ts integration, gameAdapter.ts, debug hook/scenarios, browser tests/gates, visual review.
- Design system sub-agent: icons/**, styles/tokens.css/base.css/components.css, public/fonts/** and licenses.
- HUD sub-agent: hud/**, styles/hud.css, HudLayout/StatusHud/WeaponHud with equivalent desktop tests.
- Screens sub-agent: screens/**, styles/screens.css and screen-specific tests.
- Settings sub-agent: settings.ts, settingsView.ts, settings tests (after a concurrency slot opens).

## Risks and review
Dense source/string-pinning tests need architecture-aware readers, followed by behavioral DOM tests. Stable selectors and exact story/consent wording remain. No simulation or renderer writes outside HitConfirmation compatibility entry. Three whole-gallery critique/fix rounds at 1080p and 720p, all required gates including authored rooms and verify (known missing Blender failure reported honestly). Small logical commits, no push/PR/merge.

## Integration and visual review record
- Architecture split landed green: 1,563 tests + production build. Original hooks and recovery retained.
- Round 1 (1080p): hierarchy and state coverage; corrected centered card copy, family/fire meaning, action glyph sizing and washed-out cooldowns.
- Round 2 (720p whole gallery): tightened title bounds, improved settings typography/density, preserved per-tab Resume and clear scroll affordances.
- Round 3 (1080p whole gallery): balanced result statistics, pinned pause controls, staged close-camera kiting and optional radar; fixed held-Space accepting an autofocus boon through the existing smoke invariant.
- Lead art review: replaced text rails with true-bearing ellipse chevrons (types, distance, clusters, actual hostile projectile trajectory); quieter north-up radar with oriented marine and camera footprint; elemental readiness/Overdrive, ammo/reload feedback, keyed arc reticle and larger element/crit/kill numerals.
- Follow-up self-review at both sizes: full-circle spread fixture, combat floats yield to chrome, compact rig profiles with all four element accents, fixed footnote, HUD lip legend. UI projection now runs after the renderer's current camera pose.
- Full Chromium and macOS Metal flags now match the capture harness in production smoke runners; all native input, persistence, audio and authored-route assertions remain. Two Vitest workers avoid CPU contention with the existing expensive geometry assertions; no assertion or timeout was relaxed.
- Capture-clock review: freeze pooled UI time alongside simulation in the opt-in debug hook; explicit steps advance both clocks. A regression test and capture assertion require visible damage numerals in the kiting burst.
- Final galleries use eleven rooms covering all ten environment moods, every screen, all four rig previews, ability states, reload/low ammo, critical health/damage lag, radar, and spread/kiting combat.

## Adapter seams after merge
- A1: `abilities.snapshot`, `chooseRig(id)`, `useAbility(slot)`, `rig-select` phase/status, `stats`, and actual damage/critical/lethal metadata. Existing contact and enemy-attack events remain supported. InputController owns Shift/Q/F/V.
- G1: `setGraphicsOptions(partial)` and `graphicsOptions`; optional `worldToScreen(x,y,height)` returns CSS pixels. Existing public camera matrices support current and follow cameras, floor footprints, text and bearing projection without renderer edits.
- Optional future positioned room objectives can join boss/champion radar targets; current authored non-positional objectives stay in the header.
- Fonts: original unmodified Barlow Regular/SemiBold and Barlow Condensed SemiBold, SIL OFL 1.1, self-hosted with distributed license. No npm dependencies added.
