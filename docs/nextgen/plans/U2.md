# U2 experience implementation plan

## Decisions
- Keep simulation, input, rendering and audio implementation untouched. `gameAdapter.ts` owns optional G1 camera and S2 director feature detection, with exclusive legacy sound fallback.
- Presentation time is explicit and independent: bounded hit-stop and final-kill slowdown feed a fixed-step accumulator; debug stepping bypasses both by default. State-transition beats defer only blocking screen display and input, never checkpoint writes or simulation outcomes.
- Noninteractive overlays use a bounded lifetime controller and never acquire focus. Reduced motion preserves the information while suppressing movement, flashes and time effects.
- Desktop composition targets 1280×720 first, then scales to 1080p. Route is a complete actual run graph, results hierarchy is damage/build-led, and the front door has original ship-system composition independent of 3D.

## Disjoint modules
- Lead: application, adapter, feel, beats, integration tests, visual art direction, full gates and commits.
- Screens: screens/**, screens.css, settingsView/settings.css, screen/settings tests.
- HUD/onboarding: hud/** excluding beats, HUD/combat/radar/reticle styles, onboarding module/styles and tests.
- Harness: scripts/nextgen/** (debug seam coordinated), capture tests.

## Risks and validation
- Existing source-pinned presentation assertions need equivalent behavioral guarantees; no gameplay/navigation/accessibility/persistence safety assertions removed.
- Fixed-step replay compares identical simulation input sequences with feel enabled/disabled. Audio fixtures verify director presence suppresses legacy dispatch and G1 absence stays safe.
- Required baseline plus all rig scenarios; three critique→fix galleries at 1080p and 720p; final galleries u2-final/u2-final-720. Full engineering gates and npm run verify; known missing Blender reported separately.
- No dependencies, other checkout edits, sparse changes, pushes, PRs or merges.

## Shipped architecture and integration notes

- Logical local implementation commits keep timing/adapters, HUD/onboarding, primary screens, capture v2 and visual corrections separate. All work stays on this worktree branch; no dependency, simulation, renderer, audio implementation, asset, sparse-checkout or remote changes.
- `GameFeel` runs fixed 60 Hz simulation callbacks from a scaled wall-time accumulator. Heavy impacts hold 40 ms (elite deaths 65 ms), never accumulate beyond the 90 ms ceiling, cancel for dash/critical escapes; a final kill arms one 420 ms, 0.3× beat per room. The renderer receives the corresponding slow visual delta. OS reduced motion disables timing effects and camera feedback.
- `PresentationBeats` observes room/status/boss transitions and real ability receipts. Room entry yields after firing; clear/death/finale hold only menu display for 550 ms (150 ms reduced motion), are skippable and pointer transparent, never change the saved boundary, focus or ending text. HUD owns the near-slot Overdrive announcement. Low-health edges are static; existing bearing arcs remain.
- Successful-use onboarding flips/clamps after HUD relocation and is a separate tolerant `containment.onboarding.v1` preference; no checkpoint schema change. One prompt, first-room/first-minute eligibility, first-full Overdrive thereafter. Failed actions do not mark learning. Original persistent keyboard strip removed.
- Screen hierarchy: self-contained sectional-hull title and real Continue summary; full actual ship descent graph with single destination pane and original legacy branches; four hero result counters, source composition, secondary telemetry and visible build; all rig shapes (including self buffs), compact settings, keyboard/mouse diagram, augment and family progress.
- Combat receipts remain target/source specific. Spatial fan-out prevents cross-target stacking, pooled status icon chips clarify elemental calls, and projected actor height optionally scales text. All combat decoration remains passive; native focus inspects full ability rules.
- Capture v2 retains original heavy/status/ability scenarios and adds all-default-room legal kiting, explicit beat/onboarding/feel fixtures, fixed-step sprite sheets and portable embedded comparison HTML. Missing comparison counterparts are labelled. Native simulation integration tests exercise the exact kiting scripts against all ten room geometries.

### G1 / S2 seams

- G1: existing `setGraphicsOptions`/`graphicsOptions` and optional `worldToScreen(x,y,height)` use the adapter. Camera feedback feature-detects `renderer.cameraRig` (or `renderer.rig`) exposing `addTrauma(amount)`, `kick(angle,amount)` and `punch(amount,ms)`. If the renderer already forwards the same effects to its camera, expose **`handlesCameraEffects = true`** to avoid a second kick. No renderer change is made here.
- S2: a complete four-method `GameAudioDirector` receives effects exclusively via `handleEffect`, interface/beat cues through `playUi`, and coarse environment/mix updates. Partial or absent implementations keep legacy synthesis. Legacy frozen-enemy polling is suppressed with a director. The existing `syncCombat` state bridge remains necessary for reload and weapon-switch edges because they have no `GameEffect`; keep that responsibility in one place when integrating S2.

Add actual settings mount fit, legacy arrow/number/Enter dispatch, same-name kind/reward labels, self-buff shapes and keyboard tooltip bounds.

Native mouse/keyboard actions, resizing, marine safety, pointer pass-through and held-fire assertions retained. Added a real controller regression proving reacquiring the same boon on a later expedition announces once.
- `SafeRoomLoading`: actual RAF source fixture now instantiates the real fixed-step timing controller. All loading freeze, pending input discard and user-pause invariants unchanged.
- `UiCombatPresentation`: add cross-target receipt separation, permanently pooled icon glyphs, optional projected scale, passive rules, duration rings, progress and multi-kill deduplication.
- New `UiOnboarding`, `UiBeats`, `UiFeel`: success-only learning/storage corruption/lifecycle, passive/reduced-motion/skip semantics, and seeded all-four-rig replay identity under stop/slow clocks with movement/fire/ability actions.
- `UiAdapter`: exclusive complete-director dispatch, partial fallback, angle/amount camera semantics, comfort scaling and renderer-owned-feedback suppression.
- `UiCaptureClock`, new `U2CaptureHarness` and `U2KitingFixture`: explicit timing opt-in/bypass, image stitching/compare integrity, and actual ten-room scripted action/geometry receipts. Existing ability fixture gates retained.

## Honest limits

The UI is substantially more directed and coherent, but the title is an original vector ship section rather than a cinematic character/ship render. The current world still uses the pre-G1 camera/light/VFX pipeline; fixture zoom and mocked camera contracts do not certify the future G1 view. Timing/capture diagnostics are not a hardware frame-budget certification. Beat fixtures are labelled UI fixtures; real simulation input, rig uses, damage, saves and navigation have separate tests/smoke evidence. Final integration should check the camera ownership flag, S2 reload responsibility, live audiovisual timing and an organic full-run balance/play session.
