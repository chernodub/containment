# A1 Combat Rig implementation plan

- Preserve legacy `newRun(seed)` -> starting boon with Breacher; opt-in `{rigSelect:true}` adds the rig-select phase. Keep presentation and smoke hooks untouched.
- Add a render-free AbilitySystem with an injected host, catalog-derived geometry, independent charge timers, bounded zones/deployables, normal-time cooldowns and hostile-only time scaling. AbilitySystem owns no enemy/status implementation.
- Route elemental effects and launches through MutationRuntime/ElementalRuntime. Destructible barriers stop hostile movement/projectiles, are attacked on contact, expire, and never block the marine. Use existing world LOS/traversal for all effects.
- Integrate through DepthGame and edge-triggered desktop input. Central confirmed damage reporting supplies source/applied damage/lethal metadata, statistics and Overdrive charge, including status/boon damage.
- Parallel file ownership after the core API exists: persistence/run flow data + statistics; augment catalog/draft hints; mutation/combat adapters. Main owns AbilitySystem, DepthGame, input, integration and ability tests.
- Persist only boundary-safe rig, meter and statistics; old exact-schema saves remain accepted, malformed new fields rejected. Clear transient abilities at room boundaries.
- Test each ability, walls/shapes, control resistance, events, cooldowns, blockers, time isolation, persistence, inputs, seeded replay and bounded soak. Run all engineering gates, plus verify (document pre-existing Blender failure), captures/driver and two critique/fix rounds.
- Risks: dense integration code; status damage attribution; recursive kill effects; boundaries during active Overdrive; external capture harness arrival. No new dependencies.
